# Spec — stand up cherokeenewtestament.org on Cloudflare Workers Static Assets at the theme-compatible Zola pin

Remote issue: https://github.com/CherokeeLanguage/CherokeeNewTestament.org/issues/17

## Problem

cherokeenewtestament.org does not serve. DNS for the apex resolves to an empty answer (NOERROR/NODATA — authoritative Cloudflare SOA, no A/AAAA; `www` is NXDOMAIN — dual-resolver probe 2026-11-14) — there are no records at the edge to serve from, and the origin the zone previously proxied to is dead (the 2026-11-13 probe state: apex A records at Cloudflare edge addresses but HTTPS timing out with zero bytes; the records have been removed since). The Apache-era publish path that would refresh the property (`./deploy.sh`: a `Precision-Workstation` hostname gate + rsync to `clcom@vhost.cherokeelessons.com:./cnt/public_html/`) is machine-gated dead weight — the sibling stand-up established the vhost target has no public DNS record — and the zero-byte `content/.htaccess` it copies into the build output is vestigial. The property stays dark until its serving plane changes.

This spec stands the site up on **Cloudflare Workers Static Assets** — the modern serving plane CherokeeLessons delivered (CherokeeLanguage/CherokeeLessons#31, merged via PR #38 on 2026-11-12; the site serves live — the org's worker-served-properties record classifies the shared model). CNT's conversion follows that delivered pattern with this repo's own surfaces judged — **no cargo-culting of old stuff**: the Apache-era deploy artifacts retire outright; no redirect table, no oversized-media handling, and no third-party-embed CSP origins are transplanted — only what this site's own audit justifies carries.

The toolchain side carries the developer's second directive: the build uses **the latest Zola version compatible with the vendored `themes/Zulma`** — resolved by an executed compatibility gate, not an inherited claim. Gate result: the current 0.23 line (the Tera 2 template-engine major) fails on the vendored theme's templates; **0.22.1 is the compatible winner**.

## Requirements

- **R-1 — Assets-only deployment manifest.** A tracked `wrangler.jsonc` SHALL declare `"name": "cherokeenewtestament-org"`, a `compatibility_date`, `"assets": { "directory": "./public", "not_found_handling": "404-page" }`, and `"previews": {}`. No Worker script, no bindings — the built `public/` is the deploy unit. (`previews: {}` carries its own evidence: the sibling's Workers Builds preview runs hard-errored without it under wrangler 4.153.0 — CherokeeLanguage/CherokeeLessons#31 provenance, observed 2026-10-27 — and it is re-verified against the pinned wrangler at implementation: kept unless the pinned wrangler's own behavior proves it unneeded.)
- **R-2 — Branch-aware build.** `build.sh` SHALL gain production/preview base-url logic: branch from `WORKERS_CI_BRANCH` with a git fallback resolving production-safe on a detached HEAD; production — the branch of record, `master` — builds with the base_url of record; other branches build domain-neutral (`--base-url /`) so a preview hostname serves; `SITE_BASE_URL` wins in both modes. The pin-download-and-build core (CherokeeNewTestament.org#14's delivered mechanism) is unchanged.
- **R-3 — Base URL of record.** `config.toml` SHALL carry `base_url = "https://cherokeenewtestament.org/"` — the apex canonicalized with its trailing slash; the domain is already this site's own.
- **R-4 — The theme-compatible Zola pin of record.** The tracked pin SHALL record the latest Zola release that builds this repo's vendored-Zulma tree cleanly, resolved by the executed compatibility gate recorded in Provenance: as of 2026-11-14 that is **0.22.1** — `ZOLA_VERSION` equals `0.22.1` with `ZOLA_VERSION.sha256` matching its release artifact, and the pin is not bumped ahead of (or behind) the gate's verdict. `README.md` and `AGENTS.md` SHALL state the compatibility verdict in the sibling's idiom ("currently 0.22.1 — the latest release compatible with the vendored Zulma theme"), carrying the standing rule that a future bump re-executes the gate first. The gate's executed evidence (both invocations, the Tera-2 failure and the clean build) lives in this spec.
- **R-5 — Deterministic deploys.** A tracked `package.json` SHALL pin wrangler via an exact-version `wrangler` entry — `"wrangler": "4.162.0"`, the current release at spec time (verified live 2026-11-14; the value is re-verified current at plan time).
- **R-6 — The Apache-era publish path retires, including its documentation.** `deploy.sh` and the zero-byte `content/.htaccess` SHALL be deleted from tracking. `README.md` SHALL document the Workers deploy path (a merge to `master` triggers Workers Builds → `npx wrangler deploy`; PR branches get preview builds via `npx wrangler preview`) and the one-time ops sequence (GitHub App connection; Worker creation with the manifest's name `cherokeenewtestament-org` — name-match is a builds-fail condition; build command `./build.sh`; production-branch selection set to `master`; custom-domain attachment for apex and `www`), and SHALL NOT continue documenting the machine-gated rsync-era deploy. `AGENTS.md`'s "Deploy — manual and machine-gated" section SHALL become the Workers deploy path, its `.htaccess` copying step removed, and its build/pin sections SHALL carry the R-4 compatibility verdict. The `original/` corpus, `reference/`, and the disabled `convert-01.sh` are untouched (the repo's own guards stand).
- **R-7 — Security headers derived from this site's actual embeds.** A tracked `static/_headers` SHALL set `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, and a Content-Security-Policy derived from the site's real third-party usage: `self` + the **utteranc.es** comment widget origins (`https://utteranc.es` — script and frame; the widget loads unconditionally on 288 article pages) + both origins of the theme's font load path (`fonts.googleapis.com` — the import 7 built Zulma-variant stylesheets carry, verified in the gate build — and `fonts.gstatic.com`, the origin the runtime-fetched Google CSS loads the font binaries from; no built stylesheet carries `gstatic` directly — the attribution is the load path, not a grep of the built files). The policy SHALL NOT carry third-party origins the site does not use (it embeds utteranc.es and nothing else third-party). The CSP's final form is verified at plan time against the gate build's real pages; the comment widget's continued functioning is a preserved behavior (288 pages keep their comments).
- **R-8 — No redirect surface, no oversized-asset handling.** The conversion SHALL NOT introduce `static/_redirects` (no legacy redirect rules exist to port — the `.htaccess` is zero bytes) and SHALL NOT introduce R2 or media relocation (the deploy-unit census is clean: zero files over 25 MiB, 9,140 ≤ the 20,000-file/version asset limit, zero `%-paths`). These absence requirements hold the modern path's minimal surface; they are verifiable, not assumed.

## Out of scope

- The Cloudflare-side ops actions themselves (dashboard/API work — sequenced in the plan, executed with the developer's involvement where account authorization is required).
- A theme upgrade or any `themes/Zulma` change — its own surface, never requested; R-4's gate verdict stands for the theme as vendored (upgrading the theme is the only path to the 0.23 line, and it was not asked).
- The cherokeelanguage-devops records' refresh: the worker-served-properties record's pre-conversion section and the CNT publishing runbook go stale/false at landing; those are devops-repo surfaces (single-repo split) — the devops change files when the conversion lands, per that record's own currency contract. The existing gatus edge-path entry needs no change.
- `convert-01.sh`, `original/`, `reference/` — untouched (the repo's guards stand).
- CodeQL workflow modernization (generational debt — its own ticket, unrelated to the serving plane).
- The `config.toml` → `zola.toml` rename (no functional gain — the sibling's rationale holds).

## Approach

Follow the delivered CherokeeLessons pattern as the structural precedent — assets-only Workers Static Assets, Workers Builds push-to-deploy, branch-aware build, exact wrangler pin — with this repo's own audit deciding every carried element (the developer's no-cargo-culting rule): the rsync-era artifacts retire outright; no `_redirects` (nothing to redirect — R-8); no R2 or media handling (nothing oversized — R-8); a CSP derived from the site's real embeds — the utteranc.es comment widget and the font imports — never transplanted from other sites (R-7). The Zola-pin question the developer posed is decided by the executed compatibility gate recorded here — the modern answer is the gate, not a guess — and the gate's winner (0.22.1, the latest release compatible with the vendored Zulma) is carried with its verdict stated in the README the way the sibling states its own pin. `previews: {}` carries with its evidence and an implementation-time re-verification duty against the pinned wrangler. Alternatives weighed: Cloudflare Pages — rejected (legacy platform; Cloudflare itself points new projects at Workers); a custom Worker script — rejected (unnecessary at zero redirects; assets-only stays simplest); bundling the pin bump with a theme upgrade to unlock 0.23 — rejected (a theme change was never requested and the gate shows no compatible newer release exists for the vendored theme).
